# Tier 3 — Agent / MCP First-Class Support

> The single biggest distribution multiplier in 2026: make every MCP-aware IDE
> and agent framework a first-class consumer of Backend Pro Max.

**Status:** 🔲 Not started
**Branch:** `feat/tier-3-agent-mcp` (to be created from `main`)
**Depends on:** Tier 1 (`decide`, `adr`, `design` commands to expose as tools), Tier 2 (intent classifier enriches tool responses)

---

## Overview

| # | Feature | Surface | Complexity |
|---|---------|---------|------------|
| 3.1 | MCP server (`backendpro-mcp`) | `backendpro-mcp` binary, stdio transport | High |
| 3.2 | Streaming JSON Lines output | `--jsonl` flag | Low |
| 3.3 | Tool schemas / function-calling manifest | `tools.json` static file | Medium |
| 3.4 | Citation tokens | `[BPM:domain.name.facet]` keys in every result | Medium |

All features remain **pure stdlib** for the core. The MCP server uses the
`mcp` Python SDK (optional extra: `pip install backendpro[mcp]`).

---

## Architecture Decisions

1. **MCP server is a new entry point, not embedded in `search.py`.** New module
   `scripts/mcp_server.py` imports from `core.py` and `decide.py`. Runs via
   stdio transport (the universal MCP transport for local tools).
2. **Tool granularity:** One MCP tool per public function — `search`, `compare`,
   `decide`, `adr`, `design`, `find_stale`, `search_all`, `search_stack`. Each
   tool has a typed input schema and returns structured JSON.
3. **`tools.json`** is a static file at repo root, auto-generated by a script
   (`scripts/gen_tools_schema.py`) from the function signatures + docstrings.
   Conforms to both OpenAI and Anthropic function-calling formats.
4. **Citation tokens** are generated in `core.py` at result-building time.
   Format: `[BPM:<domain>.<name_slug>.<column_slug>]`. Stable, greppable,
   deterministic. Added to every result dict as `_citation` field.
5. **JSONL** is trivial — one JSON object per result line. Added to `search.py`
   formatters.

## Task 3.1 — MCP Server (`backendpro-mcp`)

### Description

A Model Context Protocol server exposing Backend Pro Max as tools.
Compatible with Claude Desktop, Cline, Continue, Zed, Cursor, and any
MCP-aware client. Uses stdio transport (stdin/stdout JSON-RPC).

**Tools exposed:**

| Tool | Description | Inputs |
|------|-------------|--------|
| `backendpro_search` | BM25 search in a domain | `query`, `domain?`, `max_results?`, `min_score?` |
| `backendpro_search_all` | Cross-domain search | `query`, `max_results?` |
| `backendpro_search_stack` | Stack-specific search | `query`, `stack`, `max_results?` |
| `backendpro_compare` | Side-by-side comparison | `names[]`, `domain?` |
| `backendpro_decide` | Opinionated recommendation | `requirement` |
| `backendpro_adr` | Generate ADR | `title`, `context_domains[]` |
| `backendpro_design` | System design scaffold | `description` |
| `backendpro_find_stale` | Freshness audit | `domain`, `months` |

## Task 3.2 — Streaming JSON Lines Output

### Description

Add `--jsonl` flag for agent loops that consume results incrementally.
Each result is one JSON object per line (no wrapping array, no trailing comma).

**Format:**
```jsonl
{"_index":1,"_domain":"messaging","Name":"Kafka","_score":5.12,"_citation":"[BPM:messaging.kafka]",...}
{"_index":2,"_domain":"messaging","Name":"Pulsar","_score":3.87,"_citation":"[BPM:messaging.pulsar]",...}
```

For cross-domain (`--all`), each line includes `_domain`.
For compare, each line is one column: `{"_field":"Throughput","Kafka":"1M msg/s","RabbitMQ":"50k msg/s"}`.

### Subtasks

| # | Subtask | Files | Est |
|---|---------|-------|-----|
| 3.2.1 | `format_jsonl()` function — single-domain results | `scripts/search.py` | 0.5h |

| 3.2.3 | `format_jsonl_compare()` — per-field lines | `scripts/search.py` | 0.5h |
| 3.2.4 | CLI flag `--jsonl` + wire through `main()` | `scripts/search.py` | 0.5h |
| 3.2.5 | REPL support — `/jsonl on\|off` toggle | `scripts/search.py` | 0.5h |
| 3.2.6 | Tests | `tests/test_jsonl.py` (new) | 1h |

### Acceptance Criteria

## Task 3.4 — Citation Tokens

### Description

Every result row gets a stable, short, greppable citation key like
`[BPM:messaging.kafka.exactly-once]`. LLMs are instructed (in the SKILL.md)
to emit these verbatim. Reviewers can `grep -r '\[BPM:' .` in PRs to
verify grounding.

**Format:** `[BPM:<domain>.<name_slug>]` for row-level,
`[BPM:<domain>.<name_slug>.<column_slug>]` for field-level citations.

**Slug rules:** lowercase, spaces→hyphens, strip non-alphanumeric, max 40 chars.

### Subtasks

| # | Subtask | Files | Est |
|---|---------|-------|-----|
| 3.4.1 | `_make_citation(domain, row, column=None)` helper | `scripts/core.py` | 1h |
| 3.4.2 | Add `_citation` field to every result in `_search_csv()` | `scripts/core.py` | 0.5h |
| 3.4.3 | Add `_citation` to compare entries | `scripts/core.py` | 0.5h |
| 3.4.4 | Markdown formatter shows citation inline: `[BPM:messaging.kafka] ...` | `scripts/search.py` | 0.5h |
| 3.4.5 | JSON + JSONL output includes `_citation` | `scripts/search.py` | 0.5h |
| 3.4.6 | SKILL.md instruction: "Always emit [BPM:…] citation tokens when referencing results" | `templates/base/skill-content.md` | 0.5h |
| 3.4.7 | Tests — citation format, slug stability, uniqueness within a domain | `tests/test_citations.py` (new) | 1.5h |

### Acceptance Criteria

- [ ] Every search result includes `_citation` field

- [ ] Compare results include per-entry citations

## Dependency Graph

```
┌──────────────────┐
│ 3.4 Citations    │ ← Independent, start first (enriches all other outputs)
└────────┬─────────┘
         │ (results now carry _citation)
         ▼
┌──────────────────┐       ┌──────────────────┐
│ 3.2 JSONL output │       │ 3.3 tools.json   │
│                  │       │ (schema gen)      │
└────────┬─────────┘       └────────┬─────────┘
         │                          │
         ▼                          ▼
┌─────────────────────────────────────────────┐
│ 3.1 MCP Server                              │
│ (consumes all: citations, JSON, tool schemas)│
└─────────────────────────────────────────────┘
```

- **3.4** (citations) is independent — start immediately.
- **3.2** (JSONL) and **3.3** (tools.json) can be parallel, both independent.
- **3.1** (MCP server) depends on 3.4 (citations in responses) and benefits from
  3.3 (tool schemas inform the MCP tool definitions). Can start after 3.4, but
  best after all three.

### Recommended implementation order

1. **Phase A**: 3.4 (citations) — enriches every result immediately
2. **Phase B** (parallel): 3.2 (JSONL) + 3.3 (tools.json)
3. **Phase C**: 3.1 (MCP server) — the capstone

## Risk Mitigations

| Risk | Mitigation |
|------|------------|
| MCP SDK (`mcp` package) is a runtime dep | Isolated behind `[mcp]` optional extra. Core never imports it. Entry point `backendpro-mcp` fails fast with helpful message if not installed. |
| MCP protocol evolves — breaking changes | Pin `mcp>=1.0,<2.0` in extras. Wrap transport in thin adapter so internal API stays stable. |
| Citation slugs collide (e.g. two rows with similar names) | Append numeric suffix on collision within a domain. Test uniqueness in CI. |
| `tools.json` drifts from actual API | CI enforces `--check` mode. Schema is generated, never hand-edited. |
| JSONL breaks pipe consumers if a row contains newlines | Ensure JSON serialization escapes `\n` within values (Python `json.dumps` does this by default). Test with multi-line cell content. |
| MCP server latency — agent expects sub-second responses | BM25 with mtime cache is already sub-ms. Decide/design are slower but still <500ms. No network calls. |
| Agent frameworks need different schema formats | `tools.json` ships both OpenAI and Anthropic formats. Add more sections (e.g. Gemini) as needed — the generator is extensible. |

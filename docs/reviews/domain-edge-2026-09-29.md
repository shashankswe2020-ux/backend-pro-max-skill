## Limits and Lifecycle Decisions

- Workers documentation currently distinguishes Free HTTP CPU from Paid configurable CPU, default CPU from maximum CPU, and CPU from wall time. The CSV intentionally links the live limits and uses plan/trigger qualifiers rather than copying a matrix likely to change.
- CloudFront Functions retains the directly verified 10 KB code and 2 MB memory distinction. The stale 1ms assertion and monthly free request count were removed. Lambda@Edge memory and other quotas remain event-specific rather than generalized from regional Lambda.
- Durable Objects limits documentation is internally inconsistent about Free per-object storage: the general table and a later storage-full FAQ differ. No numeric storage quota was copied. The storage guide also contains a future-tense January 2026 billing passage; no current pricing conclusion was drawn from it.
- Vercel's historical row identity is preserved without recommending Edge runtime by default for new Next.js routes. Current provider guidance, not the old product label, controls deployment advice.
- Fastly VCL is still supported. Porting VCL behavior is not source compatibility. WASI 0.3 availability must be verified independently for each provider.
- Turso embedded replicas are not marked deprecated: the source explicitly says production-supported while recommending Turso Sync for new sync projects.

## Remaining Gaps

- Fastly numeric Compute limits were not verified: the attempted developer-guide `resource-limits/` and reference `compute/compute-limits/` URLs returned HTTP 404. Check the current account/service limits before sizing a deployment. No guessed replacement was introduced.
- A guessed Turso `turso-cloud/data-and-sync/embedded-replicas/introduction` URL returned 404; the successful official `/features/embedded-replicas/introduction` page supplies the evidence above. A guessed Durable Objects `platform/storage-backends/` URL also returned 404; the successful storage guide establishes persistence but not replica topology or disaster-recovery RPO/RTO.
- This review did not benchmark latency, perform deployed runtime tests, audit account-specific quota increases, or verify pricing, residency guarantees, provider SLAs, and complete runtime deprecation calendars.
- Provider-wide claims were deliberately narrowed to verified examples. Turso Sync merge/conflict semantics, Fastly SDK-specific API coverage, and cross-region failure recovery require separate deployment-specific review.

# SOTA Readiness Scan: 2026-09-29

## Scope

No repository command or workflow named `sota-scan` was found. This review
uses existing quality gates, local regression checks, prior audit findings,
and upstream testing/retrieval guidance. It is not an exhaustive security
audit, a model leaderboard comparison, or a factual review of every KB row.

## Fixed Findings

| Priority | Finding | Fix and evidence |
| --- | --- | --- |
| High | Test collection failed with pytest-cov because the KB module named `coverage` collided with the instrumentation package. | Use the package-qualified KB import and canonical module imports in test setup. Full coverage-enabled suite passes. |
| Medium | Package-scoped coverage initially measured only the KB coverage module. | CI now measures `src/backend-pro-max`, including bare imports and unexecuted modules. Whole-source measured coverage is 64%. |
| Medium | An unset or empty cache environment variable selected the working directory because `Path("")` is truthy. | Apply the home-directory fallback before constructing the path. Three environment cases tested. |
| Medium | Export similarity links indexed unfiltered rows against filtered document positions. Blank names could cause incorrect links or an index error. | Keep indexed rows aligned with documents. Regression includes leading and intervening blank names. |
| Medium | Category spelling differences produced false missing-category findings. | Normalize case, whitespace, hyphens, and underscores for comparisons; preserve display labels. Five false positives removed. |
| Low | Six exporter/test lint errors failed the CI lint gate. | Correct import ordering, an unnecessary f-string, and unused loop variables. Ruff passes. |

The historical pickle-cache finding is already resolved in the implementation:
cache loading uses NumPy with `allow_pickle=False` and JSON. No pickle migration
was needed in this scan.
